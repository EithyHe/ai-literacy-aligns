# UMAP 心理学框架交互可视化：设计要点说明

## 一、设计目标与核心叙事

本交互图的唯一核心叙事是：**心理学测量框架之间存在大量语义冗余**。不同框架（Big Five、HEXACO、IPIP-NEO 等）各自声称测量独特的心理维度，但当我们将其内部 construct 映射到统一的 UMAP 语义空间后，会发现许多框架的覆盖区域高度重叠——它们本质上在测量相似甚至相同的东西。

这张图要让读者在 3 秒内获取一个判断：哪些框架几乎等价，哪些框架真正覆盖了独特的心理空间。

---

## 二、三层信息架构

图中的信息被组织为三个层级，视觉权重从高到低递减。这一分层是整个设计的骨架。

**第一层（框架身份）** 是最高优先级。每个框架拥有一个独立的高饱和度色相（蓝、橙、绿、红、紫、青），框架名称以 14px 加粗字体标注在其所有 construct 的质心位置。读者第一眼看到的就是"这里有几个框架，它们各自占据什么位置"。框架数量控制在 8–10 个以内，过于小众的框架归为灰色"其他"类，防止色彩过载。

**第二层（覆盖范围与重叠）** 是次高优先级。每个框架用凸包（convex hull）的虚线轮廓表示其覆盖范围，轮廓颜色与框架一致。凸包从质心向外扩展约 35%，留出呼吸空间。填充色透明度极低（0.07），仅做底色暗示。两个框架凸包交叉的区域就是 overlap，无需额外标注即可自然呈现。这一层回答的问题是：哪些框架之间存在重叠，重叠面积有多大。

**第三层（Construct 个体位置）** 是最低优先级。每个 construct 以 4px 圆点表示，继承所属框架的颜色，默认不显示文字标签。这层信息属于"按需获取"——只有当读者主动 hover 或开启批量标签时才可见。这是与原图最大的区别：原图将全量 construct 标签平铺在画面上，导致中心区域完全不可读。

## 三、白色背景下的视觉策略

选择白色背景（#FAFAFA）而非深色背景，是为了与学术论文、报告等常见阅读场景保持一致。白色背景带来的挑战是彩色元素容易"飘"、缺乏沉稳感，因此做了以下针对性处理：

数据点加了 0.8px 的白色细描边，在点与点靠近或与填充区域重叠时，白描边起到分隔作用，避免颜色黏连。凸包轮廓线的不透明度设为 0.7 而非 1.0，略微降低饱和度感，避免在白底上过于刺眼。网格线使用极淡的 #F0F0F0，仅提供微弱的空间定位参考，不干扰数据层。图表容器使用白色（#FFFFFF）配合 1px #E5E5E5 边框和轻微 box-shadow，在 #FAFAFA 的页面背景上形成自然的层次分离。

Hover 时弹出的 construct 标签采用深色气泡（#333 背景 + 白字），在白底上提供了足够的对比度，确保文字清晰可读。Overlap Index 面板中高重叠数值使用深琥珀色（#B45309）而非亮黄色，同样是为了在白底上保持可读性。

## 四、交互逻辑详解

### 4.1 图例点击筛选

点击右侧图例中任一框架名称，进入单框架高亮模式：该框架的凸包轮廓从虚线变为实线、线宽从 1.5px 增至 2.5px、填充透明度微升；其余所有框架的点、轮廓、标签统一淡出至 opacity 0.1–0.15。再次点击同一框架或点击左上角"清除筛选"按钮，恢复全部显示。

这一交互解决的核心问题是：当 Big Five、HEXACO、IPIP-NEO 三个框架在图中心高度重叠时，读者无法区分哪些蓝点属于 Big Five、哪些橙点属于 HEXACO。单框架高亮让读者可以逐个审视每个框架的完整形态——它的覆盖面积有多大、形状是紧凑的还是分散的、哪些 construct 在边缘。

### 4.2 Hover 显示 Construct 名称

鼠标悬停在任一数据点上时：该点从 4px 放大至 6px，描边从白色细线变为 #333 深色粗线；点的右上方弹出一个深色圆角气泡，内含 construct 名称（11px、白色、加粗）。鼠标离开后，气泡消失，点恢复原始大小。

这一交互将第三层信息从"默认展示"变为"按需获取"，是本设计中信息密度控制的关键手段。读者在概览全局后，可以对感兴趣的区域（尤其是 overlap 区域）逐点探索，了解具体是哪些 construct 跨越了框架边界。

### 4.3 批量标签开关

左上角提供"显示 Construct 标签"按钮。开启后，所有可见数据点旁出现名称标签（10px、#666 灰色、不加粗）。当框架筛选同时生效时，只显示被高亮框架的 construct 标签，避免视觉爆炸。再次点击按钮关闭全部标签。

这一功能面向需要完整审视所有 construct 分布的专业用户（如论文审稿人），而非一般浏览者。

### 4.4 过渡动画

所有视觉状态切换（opacity、strokeWidth、fill、transform）使用 300–400ms 的 CSS transition 缓动。目的是让状态变化可被感知、可被追踪，而非瞬间跳变导致读者失去空间参照。

## 五、辅助面板：Overlap 量化指标

主图右侧的 Overlap Index 面板将空间重叠从"定性感知"转化为"定量数值"。面板列出框架两两之间的重叠系数，每一行包含：

两个框架各自的颜色标识点，框架名称对（如"Big Five × HEXACO"），百分比数值，以及一个从框架 A 颜色渐变到框架 B 颜色的条形图。高重叠（>50%）的行用深琥珀色加粗标注数值，低重叠行用灰色弱化。

重叠系数的计算可以选用凸包面积 IoU（交集/并集），或更精细的 construct 语义嵌入平均余弦相似度。前者与图中的视觉轮廓直接对应，理解成本低；后者不依赖降维，数学上更严谨。

这个面板的核心价值是：读者在图中看到"Big Five 和 HEXACO 好像挺重叠的"之后，可以在面板中确认"重叠程度是 72%"——视觉直觉与精确数值互相印证，形成完整的论证链。

## 六、技术实现备忘

**坐标轴**：标注"UMAP Dimension 1"和"UMAP Dimension 2"，不需要刻度数值，因为 UMAP 维度本身没有可解释的绝对数值含义。

**凸包计算**：使用 Graham Scan 或 Andrew's Monotone Chain 算法。计算后从质心向外扩展 30–40%。对顶点间连线使用二次贝塞尔曲线（Q 命令）平滑，避免尖锐棱角。

**色彩无障碍**：使用 ColorBrewer qualitative 调色板（Set1 或 Dark2）确保色盲友好。轮廓线的虚线样式（虚线 / 实线 / 点线）可作为颜色之外的冗余编码通道。

**配色参考**：Big Five = #2563EB（蓝）、HEXACO = #D97706（橙）、IPIP-NEO = #059669（绿）、Oregon Vocational = #DC2626（红）、Clinical Scales = #7C3AED（紫）、Values & Motivation = #0891B2（青）。框架超过 8 个时，多余框架统一用 #9CA3AF（灰）。

## 八、改进前后对比

| 维度 | 原图问题 | 改进方案 |
|------|---------|---------|
| 颜色编码 | 颜色含义不明，无图例 | 每框架独立色相 + 右侧清晰图例 |
| 框架边界 | 半透明填充大面积遮挡 | 极低透明度填充 + 虚线轮廓线 |
| 标签密度 | 全量标签铺满画面互相重叠 | 框架名默认可见，construct 标签按需展示 |
| Overlap 表达 | 仅靠视觉感知，无法量化 | 增加 Overlap Index 面板提供精确数值 |
| 坐标轴 | 无任何轴标签 | 标注 UMAP Dimension 1 / 2 |
| 交互设计 | 静态截图后交互失效 | 完整交互逻辑 + 静态图替代方案并行 |
| 背景主题 | 深粉红半透明区域混乱 | 白色干净背景，层级清晰 |
